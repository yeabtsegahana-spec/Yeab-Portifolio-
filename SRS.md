# Software Requirements Specification

## Yeab Portfolio Website

**Version:** 1.1  
**Author:** Yeab Tsegahana  
**Date:** October 30, 2026  
**Project Type:** Personal portfolio website

## 1. Introduction

This project is a personal portfolio website for Yeab Tsegahana. The website will introduce the developer, show the skills, highlight selected projects, and give visitors a way to contact the developer.

The site will be built using only HTML, CSS, and JavaScript. It will be lightweight, responsive, and easy to update without a backend or framework.

## 2. Purpose

The main purpose of the website is to present the developer professionally to recruiters, employers, teachers, and other visitors. It should help people quickly understand who the developer is, what they can do, and how to get in touch.

## 3. Scope

The website will be a single-page portfolio with a clean layout and a modern dark design. It will include:

- a hero section with name and role
- an about section
- a skills section
- a project section
- a contact section
- social links and a footer

The project will not require a database or server-side code. It will be hosted as a static website.

## 4. Target Users

- Recruiters and employers
- Teachers and evaluators
- Friends, clients, and potential collaborators
- Visitors who want to see the developer's work

## 5. Functional Requirements

### 5.1 Navigation
- The page must include a clear navigation menu.
- Navigation links should move the user to the main sections of the page.
- The navigation should work well on desktop and mobile devices.

### 5.2 Hero Section
- The hero section should show the developer's name and main role.
- It should include a short introduction or headline.
- It should include at least one call-to-action button, such as View Projects or Contact Me.

### 5.3 About Section
- The about section should include a short biography.
- It should describe the developer's background, interests, and strengths.
- It should feel personal and professional, not overly formal.

### 5.4 Skills Section
- The page should display skills in a clean, readable layout.
- Skills can be grouped by category such as frontend, backend, design, or tools.
- Each skill should be easy to scan.

### 5.5 Projects Section
- The site should include a section for selected projects.
- Each project card should contain a title, short description, and technology used.
- If available, each project should include a link to GitHub or a live demo.
- The section should be visually organized and easy to read.

### 5.6 Contact Section
- The contact section should include a simple form with fields for name, email, and message.
- The form should validate required fields before submission.
- If a backend is not used, the form can be designed for future connection to an email service.

### 5.7 Social Links and Footer
- The site should include social links such as GitHub, LinkedIn, and email.
- The footer should include a short closing message and copyright or personal branding.

## 6. Non-Functional Requirements

### 6.1 Responsiveness
- The website must work on mobile, tablet, and desktop screens.
- Content should reflow cleanly at different screen sizes.

### 6.2 Performance
- The page should load quickly.
- Large images should be compressed or optimized.
- The site should avoid unnecessary scripts and heavy assets.

### 6.3 Accessibility
- Text should be readable and have enough color contrast.
- The layout should support keyboard navigation where needed.
- Images should include alt text when appropriate.

### 6.4 Maintainability
- The code should be organized and easy to update.
- HTML, CSS, and JavaScript should be separated into logical sections.
- Content should be easy to change without rewriting the whole page.

## 7. Technology Requirements

The application must use only these technologies:

- HTML
- CSS
- JavaScript

No frameworks, libraries, or backend services are required for the initial version. The project should remain simple and easy to understand.

## 8. Design Requirements

The design should be modern, professional, and visually appealing. A dark theme is preferred to fit a developer portfolio style.

The page should include:

- a clean background color
- readable typography
- clear spacing between sections
- hover effects on buttons and cards
- consistent colors and section styling

## 9. Content Requirements

The website should include real or realistic information about the developer, including:

- name
- role or title
- short bio
- skills
- projects
- contact information

The content should sound natural and personal rather than template-based.

## 10. Acceptance Criteria

The project is considered complete when all of the following are true:

- The portfolio is fully built with HTML, CSS, and JavaScript only.
- The website contains the required sections: hero, about, skills, projects, contact, and footer.
- The page is responsive and works on different screen sizes.
- The design looks clean and professional.
- The site is easy to navigate.
- The code is organized and simple to maintain.
- The project is saved in the GitHub repository and ready to be shared.

## 11. Future Improvements

Possible future updates include:

- adding more project entries
- adding animations
- adding a downloadable CV
- adding a light mode toggle
- improving the contact form with a real email service

## 12. Final Note

This project is intended to be a simple, polished, personal portfolio that reflects the developer's skills and identity in a clear and professional way. It should stay lightweight, easy to maintain, and focused on real content rather than unnecessary complexity.
